# 理解要素の取り込み（AI学習基盤）

数学の理解マップを、MANABU2 の **理解要素（concepts）** として登録します。

AI学習基盤のスタートガイド（LMS-DEV wiki `a8b9e393b2e64053bfeab8e9e172f180`）が
勧める順序の **1 番目**です。これが入っていないと、動的出題も習熟度も、
どの要素の話なのかを言えません。

## 何を登録するか

入力は `WakaRouteKit/Sources/WakaRouteKit/Resources/prerequisites-math.json`
— アプリに同梱している、あの前提関係グラフそのものです。

| | 件数 |
|---|---|
| 理解要素 | 26 |
| 前提関係 | 30 |
| 習得段階 | 5 |

- **ExternalId には MANABU2 のコースIDをそのまま入れます。** 理解マップの
  要素はコースそのものなので、別の実体を作りません（開発ガイド §7）
- **Code** は `math.numbers.signed-numbers` の形。領域のスラッグは
  `study-cards` API が使っているものと同じ（numbers / geometry / functions /
  data）なので、2つの仕組みが同じ領域を同じ名前で呼びます
- **説明は取り込み時に MANABU2 のコースから取ります。** ここにコピーを
  置くと、コンテンツ側が書き直したときに古くなります
- **前提はすべて `required`。** このグラフの辺は「これが固まっていないと
  身につかない」という意味しかありません（クライアント共通の判断規則 §1）

## 使い方

```bash
# 1. 検証してペイロードを作る（通信しません）
python3 build_payloads.py

# 2. 何が起きるか見る（既定は dry-run。何も書き込みません）
export MANABU2_TOKEN=...
python3 import_concepts.py --org a461577a-3410-4c98-b1d5-db729f3444a1

# 3. 実行する
python3 import_concepts.py --org a461577a-3410-4c98-b1d5-db729f3444a1 --apply
```

**何度実行しても同じ結果になります。** 理解要素は Code で照合し、前提と
段階は全置換なので、2回目は「変更なし 26」になります。

## トークン

`write:content` を持つ、**その組織のカリキュラム管理者か管理者**のトークン
が要ります。**端末トークンでは書き込めません**（`user_credential_required`）。

## 先に落ちること

`build_payloads.py` は、書き込む前に次を検査して、1つでも該当すれば中止します。

- 前提関係の**循環**（どの経路で回っているかを表示します）
- 存在しないコースIDへの前提
- Code の重複、長さ超過（64文字）
- slug が未定義の要素

壊れたグラフを半分だけ登録するより、何も登録しないほうがましです。
サーバー側も循環は 400 で拒否しますが、**どこが悪いかは教えてくれません**。

## 実行する前に決めること

グラフ自身が下書きだと言っています。

> `"source": "draft — 中学校学習指導要領（数学）の系統に沿った下書き。
> 教科の判断としてレビューが必要（t-1fa7220）。"`

**登録すると、これが AI の出題と習熟度判定の土台になります。** 教科の
レビューを先に済ませるかどうかは、取り込みの前に決めてください。

## 数学だけです

他の4教科は前提関係の辺が未作成です（クライアント共通の判断規則 §1）。
辺のない教科を登録すると「どの要素も学習可能」＝「つまずきはありません」
になります。**空のグラフを登録しないでください。**
